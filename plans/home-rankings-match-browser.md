# 首页排行榜迁移与所有比赛浏览

> 状态：进行中

## 目标

首页保留 ELO 趋势，把球员排行榜移至「展开大图」进入的 `/trends` 页面。首页最近比赛区增加「查看所有比赛」入口，进入可搜索、筛选的比赛浏览页面。延续现有手机优先交互，进入页面时不自动唤起键盘。

## 需求来源

- 用户：把首页的「球员排行榜」放到「展开大图」界面，避免首页重复展示得分。
- 用户：在「我的最近比赛」中添加「查看所有比赛」选项，并提供可以搜索筛选的所有比赛界面。
- 用户后续限定：「只需要完成到 plan 阶段即可」。本次只新增本计划文档，不实施、提交、推送或部署。
- 既有使用偏好：人数不多，优先点击选人，文本输入不默认获得焦点。
- 仓库根目录 `AGENTS.md`：用户可感知变化在实施时写入根目录 `CHANGELOG.md` 的 `Unreleased`；版本与部署按单独发版流程处理。

## 非目标

- 不改变 ELO、TrueSkill、胜率或本周涨跌的计算口径。
- 不改个人档案页现有的比赛记录与胜负筛选。
- 不新增编辑、撤回比赛功能；首页已有撤回功能保持原状。
- 不新增数据库表、第三方依赖、服务端分页 API 或导出功能。
- 不新增底部导航项，不调整与本需求无关的页面。
- 本计划不包含版本升级、git commit、push 或部署；此前 v1.5.3 发版已经完成。

## 关键决定

### 已明确的范围与代码事实

- 首页 `HomeTrend` 的「展开大图」链接已指向 `/trends`，复用该页，不新建弹窗或第二个趋势页。
- 排行榜复用 `Leaderboard`，保留 ELO／TrueSkill 切换、胜率、本周涨跌、本人高亮和球员档案链接。
- 首页 `WeekMatches` 在有身份时展示本人最近 4 场，无身份时展示本周比赛；这两种预览行为保留。
- `listMatchesByDate()` 已返回全部比赛与四位参赛者姓名，顺序为比赛日期、录入时间、ID 升序；新页可直接使用现有仓储数据。
- `buildStatsData()` 已返回排行榜需要的球员、比赛、评分及历史，趋势页无需再重复读取一套比赛数据。

### 建议方案（供用户评审，不冒充已确认）

- 排行榜位置：放在 `/trends` 大图下方，图表和排行榜各占一行；排行榜始终代表当前全部球员，不随图表的日期或成员选择变化。排行榜旁标注「当前排名」，避免与图中历史读数混淆。
- 首页布局：移除排行榜后，最近比赛卡片占据原双栏区域的整行，预测卡片仍放在其后。
- 所有比赛范围：默认全俱乐部、全部日期，不因当前身份自动限制成个人比赛。
- 入口：有身份时保留「全部战绩」到 `/players/<myId>`，同时增加「查看所有比赛」到 `/matches`；无身份时保留原有「全部球员」并增加同样的新入口。手机窄屏允许标题和入口换行。
- 页面形态：独立 `/matches` 页面，标题「所有比赛」，提供返回首页链接；只补 `AppShell` 页面标题映射，不增加主导航项。
- 筛选：姓名文本搜索、单个球员点选、起止日期、清空筛选；第一版不增加所选球员胜／负筛选。
- 球员选择：人数少，显示「全部球员」和球员姓名按钮，可换行；单选，切换到「全部球员」取消限制。无需先展开输入框。
- 搜索：只匹配参赛球员姓名，去除首尾空格、忽略英文大小写；任意一位参赛者姓名包含关键词即命中。第一版不引入拼音或多关键词语法。
- 组合规则：姓名搜索、球员 ID、日期范围取交集；点选球员按 ID 匹配任意队伍位置，避免重名误选。日期按比赛日期 `playedAt`，包含开始和结束当天，可只填一端。
- 无效日期范围：开始晚于结束时，显示「开始日期不能晚于结束日期」，不显示误导性的比赛结果；纠正后恢复结果。清空筛选恢复全部比赛。
- 列表：按 `playedAt`、`createdAt`、`id` 降序，先筛选再截取；每次显示 20 场，点击「加载更多」再增加 20 场。筛选变化重置到首批 20 场，显示匹配总数和已展示数量。
- 比赛展示：比赛日期、A/B 两队姓名、对应比分、获胜队标识；不使用无明确个人视角的「我方」「胜／负」，不添加单人 ELO 涨跌。球员姓名链接至个人档案。
- 状态：无任何比赛显示「还没有比赛记录」；筛选无结果显示「没有符合条件的比赛」与清空筛选按钮；加载完显示「已展示全部 N 场比赛」。
- 数据与状态：服务端动态读取全量数据，客户端纯函数筛选和渐进展示，沿用现有小俱乐部规模的页面模式。筛选仅保留在当前页面状态，不增加 URL 分享或跨刷新持久化要求。
