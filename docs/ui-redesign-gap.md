# UI 重设计 gap 清单

COURTSIDE 重设计第一轮已落地：主题令牌、外壳（侧栏 / 顶栏 / 手机底栏 / 头像菜单）、总览、球员目录、球员分析、全员趋势、记分、报名。本清单覆盖尚未出原型、只做了主题适配的页面，供下一轮设计参考。设计原则与令牌见 `mock/DESIGN.md`。

## 配对 /schedule

- **现状**：在场球员头像网格多选 → 总场次步进器 → 高级选项折叠（随机种子、温度 λ）→ 生成按钮。结果区每场一张卡片：头像堆叠 + 队名、「A 队胜率」链接到 /predict 预填、整卡链接到 /record 预填记分；底部灰底小字指标条（出场方差 / 接近度 / 阵容熵）。结果按身份存 localStorage。
- **差距**：结果卡片是通用白卡列表，没有 COURTSIDE 的双队对峙构图；A/B 队未使用队色（记分板为 A 黄绿 / B 浅蓝）；场次编号、胜率没有数字排版（font-num）主角化；指标条与整体风格脱节。
- **建议设计要点**：结果改为双队卡片，A/B 队色与记分板一致（--team-a / --team-b，队色不代表胜负）；保留并强化预填记分入口（球场边核心路径）；场次序号、胜率用大号数字 + 细分隔线；指标条改为细球场线风格的脚注行。入口考虑加入桌面主导航（目前只在二级导航）。
- **优先级**：高（每周球场边高频使用，且是记分的前置入口）。

## 预测 /predict

- **现状**：顶部双队面板（已改用 team-a / team-b 令牌着色），下方 A、B 两组球员网格多选；选满 4 人后显示「A 队胜率」单条 ELO 进度条，未选满显示提示条。支持 /schedule 带参预填。
- **差距**：结果只有一条细进度条，胜率这个数字主角没有视觉地位；双队面板是浅色 tint 块，缺少记分板式的对峙张力；无 VS 构图。
- **建议设计要点**：胜率改为大数字 font-num 居中呈现，A/B 分列两侧形成 VS 构图；结果区可借鉴记分板的 bg-court 深底（两主题恒深色）；队色继续与记分板一致；保留与配对页的互跳预填。
- **优先级**：中（使用频次低于配对，但改动量小、与配对可同一轮设计）。

## 周报 /weekly 及 OG 分享图

- **现状**：周选择器 + 标题卡；出勤榜 / 战绩王 / ELO 涨跌榜（前五，奖牌色名次）、最佳组合、本周趣闻（最胶着 / 惨案 / 连胜王 / 最大冷门四小卡）；底部「生成分享图」带进度条、Dialog 预览与下载。OG 图为服务端渲染竖版：三榜领奖台样式、最佳组合、趣闻、底部日期 + 俱乐部名 + 二维码。
- **差距**：页面是白卡列表堆叠，缺数字排版与细球场线；奖牌色（金 / 银 / 铜）是 COURTSIDE 调色板之外的色相；趣闻区是四张同构小卡，与「避免给每个字段套小卡片」的原则有张力。
- **建议设计要点**：沿用 COURTSIDE 数字排版、配色和细球场线重做榜单（大数字 + 分隔线代替卡片）；趣闻可改为单列数据行；分享图属品牌物料，重设计时**保留日期、俱乐部名称及二维码**，版式与网页榜单同源。奖牌色若保留需限制在名次徽标小面积使用。
- **优先级**：中（社交传播物料，视觉收益大；但功能已完整）。

## 管理 /admin

- **现状**：口令登录；比赛管理（按时间倒序列表、改比分、删除、分页加载更多）；球员管理（改名、选择目标合并、无比赛记录时可删除）。全部操作用 confirm 确认。
- **差距**：纯工具页，主题适配后差距主要在信息密度与桌面布局：单列卡片列表在桌面偏空；比赛行可表格化；危险操作仅浏览器 confirm。
- **建议设计要点**：保持工具属性不做风格化；桌面可双栏（比赛 / 球员）或表格化比赛列表；删除 / 合并等危险操作统一为应用内确认模式；改比分沿用记分数字排版。
- **优先级**：低（仅管理员使用，功能优先）。

## 更新日志 /changelog

- **现状**：服务端直解析根 `CHANGELOG.md` 的 What's New 渲染时间线；Unreleased 段用 primary 高亮圆点与胶囊，已发布版本为次级圆点。
- **差距**：整体与 COURTSIDE 已大致相容；版本号与日期未用数字排版；时间线较素。
- **建议设计要点**：**继续直接解析根 CHANGELOG.md，不建第二份日志数据**；版本号、日期改 font-num；可给最新版本加「当前」标识。
- **优先级**：低。

## 我的 /me

- **现状**：当前身份卡（打开 IdentityPicker 切换 / 新增球员）、「关于」（更新日志入口）、「管理」（管理员登录入口）三个区块。
- **差距**：身份切换已被 AppShell 右上角头像菜单（及桌面侧栏底部）承载，/me 首屏职能与外壳重复，页面定位模糊；但「我的 / 关于 / 管理」完整入口仍需保留（DESIGN.md 明确要求）。
- **建议设计要点**：重新定位为「关于与设置」聚合页：身份区弱化为与头像菜单一致的当前身份展示（入口仍保留），主题切换、更新日志、管理员入口、俱乐部信息归拢此处；避免与头像菜单在视觉上重复竞争。也可考虑并入个人主页快捷方式（按当前身份直达 /players/[id]）。
- **优先级**：低–中（功能可用，定位问题不阻塞使用）。
