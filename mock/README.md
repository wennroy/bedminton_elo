# COURTSIDE · UI 设计原型

这是「卷技术小分队」的独立设计评审原型。示例人物和比赛均为虚构，不连接真实服务；所有交互仅在当前浏览器里演示。

## 查看

在仓库根目录运行 `python3 -m http.server 4173 --bind 127.0.0.1 --directory mock`，打开 http://127.0.0.1:4173 。也可直接打开 `mock/index.html`。

路由：`#overview` 总览与每周名句、`#players` 球员列表、`#player/1` 球员分析、`#record` 记分、`#signup` 每周报名、`#trends` 全员 ELO 趋势。右上角切换 light / dark，记住手动选择；首次进入跟随系统。浏览器宽度决定手机、平板、桌面布局。

## 本轮设计范围

- 总览：每周名句、个人摘要、本周报名、全员 ELO 趋势、排行榜、最近比赛。鼓励性文案只在顶部名句出现。
- 每周报名：名单、成员数与含小伙伴总人数、自己来 / 带一人、人数更新、取消报名、身份切换、首页同步。
- 全员趋势：默认所有成员，近 4 / 12 周 / 全部，ELO / 排名模式，成员多选、全选 / 只看自己 / 清空，触碰或聚焦日期查看当时排序。
- 球员分析：任意球员档案、积分趋势与周期选择、搭档及对手分析、比赛记录与胜负筛选。
- 记分：四个球员位置、搜索选人、防重复、直接输入及增减比分、换边、提交确认、积分反馈、继续记分。
- 外壳：手机底部导航、桌面侧栏、主题切换、身份选择。

自动配对、预测、周报、管理、更新日志尚未制作完整原型。生产实现时必须保留现有入口和功能。

## 文件

- `index.html`：启动文档、主题初始化。
- `styles.css`：主题语义变量、组件、三个尺寸的布局。
- `data.js`：确定性虚构比赛，按当前仓库 ELO 公式计算演示数据。
- `app.js`：页面和本地交互。
- `community.js`、`community.css`：每周名句、报名、全员趋势与相关响应式样式。
- `DESIGN.md`：设计原则、组件状态、数据映射、交接说明。
- `PLAN.md`：本轮原型制作与验收清单。
- `check.py`：浏览器验收与截图脚本，使用方式见 `DESIGN.md`。

原型的赛后分析从同一组比赛派生；新增演示比赛刷新后消失。身份和主题保存在 `courtside-` 前缀的 localStorage 中。原型确认弹层会明确标注模拟操作。

每周名句使用六条原创样例按上海时区周一确定展示内容，同一周固定，支持浏览往期；这仅演示产品行为，没有接入自动文案生成服务。生产每周生成与持久化规则见 `DESIGN.md`。演示报名同样只存在内存中，刷新后恢复。
