# COURTSIDE / 专业运动记分牌

## 已确认的设计方向

用户的两个核心场景：球场上用手机记分；赛后用手机、电脑及平板查看每位球员的详细分析。视觉采用专业运动记分牌风格，并提供浅色 / 深色切换。本轮将近期状态放在分析页上半屏，搭档与对手放在后面；分析优先级尚待用户试用反馈。

第二轮用户反馈：减少全站励志文案，仅在首页顶部保留“每周名句”，每周生成一句；补齐每周报名和全员 ELO 趋势。第二轮原型已纳入这些要求，手机底栏第四入口改为报名，身份切换保留在右上角头像及报名 / 记分页。

原型位于 `mock/`，为实现 agent 提供可交互视觉参考。不是生产页面改造，不应把模拟数据或原型脚本复制到生产数据层。

## 视觉原则

1. 比分和数据是视觉主角。用数字尺度、分隔线和布局建立层级，避免给每个字段套一张小卡片。
2. 暖白与石墨黑承担阅读；黄绿承担主操作和选中态；A 队黄绿、B 队浅蓝。队伍颜色不代表胜负。
3. 使用细线球场标识、略倾斜的俱乐部图标和紧凑数字，建立运动气质。没有大幅装饰插图或图片加载依赖。
4. 中文是操作及阅读语言。少量英文是功能性栏目眉题，不能替代中文标签。鼓励性 / 励志文案只允许出现在首页每周名句，其他标题、侧栏和页脚直接描述功能或数据；不得重新加入“每一次挥拍，都值得记下来”一类装饰文案。
5. 个人档案的结构依次回答：现在如何 → 最近如何 → 和谁配合 / 交锋 → 具体发生了什么。

首次访问跟随系统；手动切换优先并持久化。尚未手动选择时响应系统变化。生产主题初始化应在首屏绘制前执行，避免闪白；必须同步 `color-scheme`、表单控件、弹层、图表提示框和 `theme-color`。

用户只要求 light / dark 两种切换，本轮未另做主题设置页。以后如增加“跟随系统”选项，应清除手动偏好并重新订阅系统设置。

## 字体、间距与组件

- 中文使用平台中文字型（macOS / iOS 上 PingFang SC，其他平台回退到 Hiragino Sans GB / Microsoft YaHei / sans-serif）；英文优先本机 Avenir；数字优先 DIN Alternate / Bahnschrift。无外部字体请求。
- 字体实际外观受平台影响。生产若要求跨端高度一致，可选择有合法许可的自托管数字字体；不要依赖国外字体 CDN 才能显示正文。
- 页面标题桌面 30–31px、手机 26–27px；栏目标题 15–17px；主要数据 38–43px；记分板数字 84–103px。
- 页面内容正文 / 控件以 12–14px 为主。9–11px 仅用于日期、眉题及辅助标注；用户评审后可以整体上调手机数据表的辅助字号。
- 主要面板圆角 16px，按钮 9px，面板内边距 20–25px，模块间距 18–24px。
- 记分主按钮高度 51–52px，增减按钮至少 44px；主要表单输入高 44px。所有小图标必须具备文本或无障碍名称。
- 增长同时显示 `+` 和绿色，下降同时显示 `−` 和红色；胜负写明“胜 / 负”，不单靠颜色表达。
- 大多数面板只用边框，无悬浮阴影；阴影用于弹层。入场仅使用 300ms 的轻微移动和淡入，尊重减少动态效果的系统偏好。

## 响应式行为

| 宽度 | 导航 | 分析布局 | 记分布局 |
| --- | --- | --- | --- |
| ≤760px | 底部四入口，顶部品牌和主题 | 指标 2×2；趋势、近期状态、搭档、对手、历史依次展开 | 双队并排；隐藏说明侧栏；底部预留安全区 |
| 761–1000px | 紧凑图标侧栏 | 指标四列；趋势与状态并列；搭档与对手并列 | 记分板加紧凑说明栏 |
| 1001–1190px | 较窄文字侧栏 | 保持分析并列，减小间距 | 双栏 |
| ≥1191px | 222px 文字侧栏 | 完整分析面板，页面最大宽度 1480px | 记分主板与说明栏，内容最大 1060px |

手机历史记录把日期移到行顶部、ELO 变化放到右上角，保留双方阵容和比分。排行榜在中等桌面宽度暂隐藏胜率辅助列，但球员档案仍可查看。手机球员列表为两列，桌面为三列。

横向内容不能通过禁止缩放解决；原型 viewport 允许用户缩放。生产 `layout.tsx` 当前的 `maximumScale: 1` / `userScalable: false` 应在这轮适配中重新评估并允许缩放。

## 页面和交互

### 总览 `#overview`

顶部展示唯一一条每周名句，下方是个人数据 / 记分主入口与本周报名并排。全员趋势位于排行榜和最近比赛之前。“我的数据”进入当前身份的球员档案。当前比赛数据与报名参考日期固定为 2026-09-07，原型里的“今天”不是系统实时时间；名句演示使用浏览器实际时间，并统一按上海时区计算周。

### 每周名句

- 展示“每周名句”、所属周起止日期、一条短句与“原创 · 每周一更新”。原型目前使用原创样例，不冒充真实人物名言。
- 以 Asia/Shanghai 周一 00:00 为新一周起点。同一周所有人看到同一句，刷新、主题切换和设备变化不导致内容变化。
- 原型用六条原创句子按周轮换，只演示按周固定及往期浏览；没有调用模型、创建定时任务或实现真实每周生成。
- 正式实现每周生成一条约 12–26 字的简短原创句子，与打球、配合或练习有关。文风自然克制，避免空泛说教；整站仅此处保留这类文案。
- 生成在服务端完成，按周起始日期作为唯一键持久化结果；不能由每位访客在客户端分别生成。正常周一生成一次，重试必须幂等；失败沿用上一期并保留上一期日期标识，无历史时隐藏名句区域，不阻挡记分和报名。
- 上一周 / 下一周箭头浏览已有历史，当周禁止前进。原型往期来自样例轮换，生产只允许查看真实已存档内容。
- 用户尚未确定要“原创生成”还是“真实名人引用”；当前按原创设计。如果选后者，必须显示作者及可核验来源，不生成虚假归属。

### 每周报名 `#signup`

- 沿用 `web/src/app/signup/page.tsx` 的每周三 18:00–20:00 场次；原型展示 2026-09-09。未增加仓库没有的地点、费用、名额或截止提前量。
- 场次卡同时显示参加总人数、报名成员数、随行小伙伴数，定义为 partySize 总和、报名记录数、二者差值。
- 名单按报名先后顺序显示，附“本人参加”或“携带 1 位小伙伴”。成员可进入球员档案。
- 未报名：选择“自己来”（1）或“带一位小伙伴”（2），确认后加入名单；按钮变为已报名状态和取消入口。
- 已报名：切换人数立即更新，名单、统计、首页报名卡同步；取消先确认，可以保留报名，也可移除本人及随行人数。
- 切换身份后按该成员已有报名恢复状态，未报名者默认 1 人。原型身份并非安全认证。
- 桌面名单与操作栏并排；手机操作栏在名单之前，不需要滚过所有成员才能报名。
- 生产复用 `/api/signups` 的 POST / DELETE 与现有字段。保留管理员移除他人报名的能力，本轮普通成员原型未展示管理员操作。
- 场次切换沿用 `getActiveSessionDate`：上海时间周三 20:00 前仍为当期，20:00 起为下周。演示的固定日期不会实际滚动场次，不能照抄到生产。

### 全员 ELO 趋势 `#trends` 与首页

- 默认显示全部 8 位示例成员，近 12 周。首页有完整可操作图表，另提供独立大图页。
- 周期为近 4 周 / 近 12 周 / 全部；类型为 ELO 积分 / 排名。类型或周期切换不清除成员选择。
- 每位成员有稳定 ID 对应颜色，浅深主题分别提供八种可读颜色。图例使用姓名、选中对勾和颜色，不能只用颜色说明选中状态。
- 支持多选、全选、只看自己和清空；全不选显示明确空态，不自动偷偷恢复全选。
- 按比赛日生成日期轴，沿用期初已有积分作为窗口起点。生产对还未加入或尚无比赛的成员应沿用现有初始评分及记录定义，不制造虚假的早期历史。
- 触碰、悬停或键盘聚焦日期后，右侧显示该日选中成员的 ELO，按该日分数从高到低排序；手机明细放到图下两列，显示阅读日期。
- 名次为全员当日名次，筛掉别人不让自己的排名提高；名次 1 在纵轴最上。原型以显示的整数 ELO 排序，同分按 ID 稳定排列；正式版要与现有排行榜的同分口径统一。
- 原型个人图与全员图统一使用 `DATA.history`。记分产生的新日快照会同时进入两种图表。
- 复用现有 `components/home-trend.tsx` 的多成员数据、排名与 tooltip 排序思路；正式实现可继续用 Recharts，不必复制原型 SVG。

### 球员列表 `#players`

搜索按姓名过滤；按 ELO、胜率或场次排序。每张卡片进入对应球员档案。无搜索结果时保留搜索框并显示空提示。排名始终按 ELO，切换列表排序不改变排名定义。

### 球员分析 `#player/:id`

- 头部：姓名、俱乐部排名、身份标识、切换球员。
- 指标：当前 ELO、指定最近一周变化、生涯胜率、累计出场、当前连胜 / 连负。
- 趋势：近 4 周 / 近 12 周 / 全部。周期按钮只过滤趋势，不更改生涯统计。截取周期前的最后一个 ELO 作为区间起点，并明确显示区间涨跌。
- 图表按日期间隔定位，按比赛日汇总；触碰、悬停或键盘聚焦数据点显示日期与积分。
- 近期手感：近 8 场胜负顺序从左到右由早到晚；近 8 场胜率与生涯场均净胜分各有独立标签。
- 搭档：至少共同打过 3 场中胜率最高的搭档；对手：至少交手 3 场中我方胜率最低的对手。原型与现有最低样本要求一致。
- “全部”弹层列出所有搭档或对手，包括不足 3 场的样本，并标注样本较少。
- 历史：全部 / 获胜 / 失利筛选；“再看 5 场”渐进展开。生产可保留现有每页 10 场及自动加载，只调整视觉。
- 这里“我方”指当前查看的球员所在队伍，不一定是当前操作者本人。

### 记分 `#record`

1. 从四个明确的阵容位置选择球员；已占用其他位置的球员禁用；允许替换或移除当前位置。
2. 比分可以直接输入，也能 + / − 调整。前端接收 0–99 整数并禁止平局，沿用现有宽松录分规则，不强加 21 分封顶。
3. “交换两边”一起交换阵容和比分，避免错配；“清空阵容”保留比分，并提示保留结果。
4. 四人未满、重复、平局或非法分数时不能确认，按钮下说明原因。
5. 确认弹层显示双方阵容和比分；返回修改不写入记录。原型按钮明确写“演示记分”。
6. 演示提交只追加到内存的 `MATCHES`，按仓库双打 ELO 算法重算；成功展示四人的前后积分和变化。所有分析视图随之更新，刷新回到初始示例。
7. 成功后“再记一场”保留阵容并将比分重置为 21:0；用户可直接替换人。“查看我的数据”进入录入者档案。
8. 同一提交标记防止演示重复点击追加；关闭成功弹层后入口变成“继续记下一场”。生产仍应沿用提交中禁用与必要的服务端防重复策略。

原型默认选中示例身份林一以便快速评审。生产不能默认冒用任何球员身份，应保留当前身份选择 / 新增球员流程。

## 生产状态要求

以下是实现时的必要状态约定，本轮原型主要演示成功流程、无搜索结果、选人禁用和非法比分；没有模拟真实网络。

| 状态 | 设计行为 |
| --- | --- |
| 尚未选择身份 | 记分前展示身份选择；可浏览公共数据；确认按钮不可用 |
| 没有球员 / 新球员无比赛 | 显示语义空态；ELO 沿用初始值；胜率为“—”，无历史图；黄金搭档 / 对手提示满 3 场解锁 |
| 正在加载数据 | 保留标题和页面布局，用对应形状骨架占位，避免页面跳动 |
| 正在提交 | 主按钮显示“正在记录…”且禁用；阵容及比分保留；成功前不显示积分变化 |
| 提交失败 / 网络断开 | 原位置显示错误与重试操作；保留输入；不显示成功反馈或清空比分 |
| 无筛选结果 | 在列表区域说明没有符合条件的记录，筛选入口保留 |
| 长名字 | 列表内截断，档案头部和选人弹层可查看完整名字；不得挤压比分 |
| 辅助功能 | 键盘可遍历控件；弹层限制焦点且支持 Escape；关闭回到触发控件；反馈有 live region；允许页面缩放 |

## 验收方式

`python3 mock/check.py` 对本地 4173 静态服务执行浏览器检查。可用 `--browser /absolute/path/to/chrome-headless-shell` 指定已安装浏览器，`--screenshots /tmp/courtside-preview` 指定截图目录。需要 Python Playwright 环境。

覆盖 360 / 390 / 768 / 1024 / 1440px、六个页面、浅深两种主题，共 60 组；检查横向溢出、名句周一边界 / 同周稳定、全员趋势选择 / 日期排序 / 排名、报名与取消 / 人数更新 / 身份切换 / 首页同步，以及原有搜索、筛选、主题持久化、阵容防重复、比分校验、换边、确认返回、积分反馈及刷新隔离。截图供视觉人工检查。

这不等同于真实 iOS Safari、Android Chrome 的触摸键盘和安全区测试；实现前应在实际设备上验证这些体验。
